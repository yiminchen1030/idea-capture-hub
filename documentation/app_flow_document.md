# App Flow Document for AI-assisted Idea Recording Application

## Onboarding and Sign-In/Sign-Up
When a new user arrives, they land on the public homepage of the application. This page offers clear prompts to create an account or sign in. To sign up, the user clicks the "Sign Up" button and is taken to a form where they enter their email address and choose a secure password. Once they submit the form, the application sends a confirmation email. After the user clicks the link in that email, their account becomes active and they are redirected to the sign-in page. Social login options such as Google or GitHub are also available and can be chosen instead of filling out the email form. To sign in, the user provides their email and password or taps the social login button and completes the external provider’s flow. After successful authentication, they land on the protected dashboard. If the credentials are invalid, the user sees a friendly error message prompting them to retry. A "Forgot Password" link is available on the sign-in page. Clicking this link leads to a page where the user enters their email to receive a password reset link. After following the link and setting a new password, they can return to the sign-in page and access their account. A "Sign Out" control appears in the main navigation once the user is logged in. Tapping it immediately clears the session and takes the user back to the public homepage.

## Main Dashboard or Home Page
After signing in, the user sees the main dashboard, which greets them by name and displays a top navigation bar containing the app logo, a theme toggle, and a user menu for quick access to profile settings and sign-out. Below the navigation, the page is divided into two sections. On the left, there is the idea submission form where the user can input the core elements of their idea: the product, the customer, and the business model. On the right, the application lists previously saved ideas in a scrollable card layout that shows the product name and a short preview of the business model. The header includes a button labeled "Get AI Suggestions" next to the business model field in the form. This button triggers the AI assistant. The user can easily switch between writing a new idea and reviewing old ones. Every element on the page is interactive, and clicking any idea card expands it to show full details and options to edit or delete.

## Detailed Feature Flows and Page Transitions
### Idea Submission Flow
Once on the dashboard, the user focuses on the idea form at the top of the left section. They type a brief description of the product into the first field and then describe the target customer in the next. In the business model field, the user can either write their own text or tap the "Get AI Suggestions" button. When the user completes all fields, they click the "Save Idea" button below. The form visually shows a loading indicator as it sends the data to the server. If the save operation succeeds, the form clears and the new idea appears at the top of the idea list on the right.

### AI Suggestion Flow
When the user clicks "Get AI Suggestions" next to the business model field, a modal appears with a spinner while the app requests ideas from the AI service. The request bundles the product and customer context and sends it securely to the server-side AI endpoint. When suggestions arrive, the modal lists them as selectable text blocks. The user can tap any suggestion to fill the business model field automatically, close the modal, and then proceed to save or refine the suggestion manually.

### Idea Listing and Editing Flow
The list of ideas on the dashboard updates automatically whenever a new idea is saved. Each idea card shows the product name and the first line of the business model. Clicking a card expands it inline so the user can see and edit all fields. In expanded view, the user finds "Edit" and "Delete" buttons. Tapping "Edit" transforms the display into an editable form prefilled with the idea’s data. After making changes, clicking "Update" sends a PUT request to the server and refreshes the card. Tapping "Delete" prompts for confirmation; confirming sends a DELETE request and removes the idea from the list.

### Navigation Between Pages
The user menu in the top-right corner of the navigation bar includes links for "Profile Settings" and "Sign Out." Clicking "Profile Settings" transitions the user to a dedicated account management page. After completing modifications there, the user clicks "Back to Dashboard" and returns to the main flow. Using the browser’s back and forward buttons also respects the protected routes, ensuring the user remains signed in and sees the dashboard first when navigating back after visiting another section.

## Settings and Account Management
The profile settings page is accessible from the user menu in the top navigation. On this page, the user sees a form with fields for their display name, email address, and an option to change their password. To update the password, they enter their current password, pick a new one, and confirm it in a second field. The page also includes a toggle for dark or light mode preferences and notification settings such as receiving a weekly summary email. After the user clicks "Save Changes," the app displays a success message and retains the user on the settings page so they can verify their updates. A link labeled "Back to Dashboard" in the page header returns the user to the main application flow.

## Error States and Alternate Paths
If the user attempts to save an idea with missing or invalid fields, the form highlights the problem fields with an inline error message explaining what to fix. Should the AI suggestion endpoint fail due to network issues or invalid API credentials, the modal closes and a toast message appears at the bottom of the screen stating "Unable to fetch suggestions. Please try again later." When any API call takes longer than expected, spinners and loading states appear to reassure the user that the operation is in progress. In the event of losing internet connectivity, the user sees a persistent banner at the top warning of offline status; during this time form submissions and suggestion requests are disabled until the connection returns. If an unauthenticated user attempts to visit a protected route by typing it into the address bar, the app automatically redirects them to the sign-in page with a message explaining that authentication is required.

## Conclusion and Overall App Journey
From first landing on the public homepage, the new user is guided smoothly through account creation, email confirmation, and initial sign-in. Once authenticated, the user works within a single protected dashboard where they can capture structured ideas by filling out a form, enhance their input with AI-driven suggestions, and immediately see their saved ideas listed for review. Account management is neatly contained in a dedicated section, enabling profile updates without derailing the main workflow. Throughout the experience, clear loading indicators, inline error messages, and graceful handling of network issues keep the user informed. By following this flow, users can reliably sign up, record, refine, and manage their entrepreneurial ideas in one cohesive application.
